# Phase 3 history draft (2026-11-11)

Base: origin/main 92a94f0cc201251b7f9297e20504984ac981edff. Local draft only; MODEL_HISTORY_ENABLED remains false.

The [Meta Responses documentation](https://dev.meta.ai/docs/protocols/responses) documents stored responses (`store=true` by default), chaining by previous_response_id, and loss of retrieval/chaining after deletion. It does not publish a numeric lifetime for response IDs. [Meta terms section 4.4](https://dev.meta.ai/legal/terms-of-service) describes retention by purpose rather than a fixed response-ID expiry. Checked 2026-11-11; no authenticated account, provider request or billing call was used. A 30-day OpenAI retention rule is not evidence about Meta. Meta's exact guaranteed ID lifetime is unverified.

The app's one-hour RESUME_MS / IDLE_MS in apps/mobile/lib/dream.ts control automatic reopening, not access to older conversations. The History sheet can open an older session; GET /dream/sessions/:id and POST /dream/turn have ownership checks but no age cutoff. dream/agent.ts modelInput rebuilds each new user turn from the latest saved transcript entries and current widgets. Response IDs only chain the tool rounds within that turn. Saved transcripts retain at most 80 entries; the model prompt uses the latest 16 prior entries.

The proposed app policy retains each temporary model-context envelope for 30 days from its database creation time. This is a draft app retention choice, not a claim about Meta. Continuing a chain creates a new bounded copy. Existing transcript replay preserves reopening beyond this temporary retention window; it does not promise unlimited model memory. Limits remain 400 input items and 2,000,000 serialized bytes, now also enforced at persistence. Old deadlines are not extended retroactively.

Migration 033 links dream envelopes to their conversation through a composite owner foreign key. Conversation deletion cascades those copies; account deletion still cascades all copies. Unassociated model calls remain account-scoped and expire normally. Account/conversation deletion racing with a new save cannot recreate orphan context. Existing pre-033 unassociated development rows expire or cascade on account deletion; no production history rollout has occurred.

Expired copies cannot be loaded. Cleanup runs before a history save, at API startup and every five minutes alongside the existing sweep. Cleanup continues when the generation flag is off so disabling generation cannot strand older copies. Cleanup failures log no chat text; expiry checks still deny access. An API that is stopped cannot physically sweep rows until it restarts. Privacy drafts describe the cleanup schedule without promising a completion deadline during failures, and distinguish saved History from temporary context.

PGlite tests cover database-clock deadlines, later continuation, expiry/cleanup, item/byte limits, owner isolation, conversation/account deletion and a late save, plus the real runTurn/modelFor path reopening an older saved conversation after its temporary context expired. They use mock responders at $0. Real Meta retention, production cleanup operations and multi-instance behavior are not claimed. Enablement needs the matching privacy draft and a coordinated client/server release; this branch enables neither flag.
